04 / 09项目 · 安卓

爱宠 App

安卓端 · 一站式宠物服务

养宠的人真正会打开的是一个 App：买东西、问症状、找门店。我把这几件事，加上一套离线的风险识别，收进同一个端里。

2025.09 – 2025.12
核心开发（AI 能力主导）
Java · Kotlin · SQLite
OkHttp · qwen-turbo · 百度语音
love-pet-android

对话
OkHttp 封装 DashScope 兼容接口，维护最近 20 条上下文，子线程请求、主线程回调，回答回来时不卡界面。
自查
按症状加权累加排序：呕吐 0.35、拉稀 0.35、食欲不振 0.15……权重按常见病先验人工设定，换回来是离线与可解释。
兜底

存储
SQLiteOpenHelper 建六张表（笔记、评论、关注、商品、收藏、购物车），全在本地。
实测在本机模拟器构建安装（compileSdk 32 / minSdk 21），跑通首页、医疗、自查结果三条主链路；自查给出「轻症」分级与 7 条带概率和科室的建议。

宠物知识库 RAG + Agent

后端 · 让回答有出处

模型其实不知道猫能不能吃巧克力。我给它一本喂养手册，要求它只按手册回答；答不出来就说不知道，而不是编一句。

2025.10 – 2026.01
独立开发
FastAPI · LangChain · Chroma
FastEmbed · LangGraph
pet-feeding-rag
pet-feeding-agent

检索
按 500 字一块、50 字重叠切开；bge-small-zh-v1.5 本地 Embedding（ONNX，免 Key），Chroma 落盘（hnsw:space="cosine"），top-4 召回。
可核验
召回片段进 Prompt 的同时，把 sources（原文 + 距离）一起返回，答案对不对可以当场翻手册核对。
智能体
LangGraph ReAct，三个工具——知识库检索、AST 安全计算器、联网搜索——由模型自己挑，可多轮调用；计算器走白名单解析，不用 eval。
降级
没配 Key 或调用失败时自动退回纯检索模式，接口不报错、链路不断。
实测配 Key 前 mode=retrieval_only；配 Key 后同一次调用切到 mode=llm，仍回 4 条片段（余弦 0.4568 – 0.4909），全部来自 pet_feeding_manual.md。Agent 三个工具都是模型自己挑的：巧克力→知识库、50 克×3 顿→计算器 150、宠物展→联网两次后如实说查不到。

07 / 09DEBUG

排障

THREE BUGS I FIXED

评分全返 60

配好 Key、同一份答案连打 5 次，还是全 60 分。真因是旧的 uvicorn 进程还占着 8000 端口，pkill 抓不到它；按端口找到进程 kill 掉再重启，评分才回到 88 – 92。

装不上 chromadb

本机 pip 装 chromadb 直接 ResolutionImpossible——Mac 上的 Python 3.14 没有对应轮子。换到 Python 3.12 的云主机一次装成，mode 从 retrieval_only 变成 llm。

查不到就说不查不到

Agent 被问「2026 年深圳宠物展会」，联网搜了两次没有可靠结果，就如实说查不到，不补一个像真的日期。
